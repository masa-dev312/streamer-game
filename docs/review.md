# 企画レビュー記録(v2.0 草案 → v2.1)

実施日: 2026-10-12 / 対象: [planning.md](planning.md) の v2.0 草案(視聴者は参加しない、招待した参加者だけでワナを仕掛け合う案)
これまでのレビュー記録は共有フォルダの 旧案/ にあります。

今回から、ユーザーの依頼で**配信の専門家**を加え、4つの視点でレビューしました。いずれも Claude がその立場を想定して行ったもので、実在の専門家や実際のユーザーに聞いたものではありません。

## 4つの視点が共通して見つけた穴
**配信の覗き見(ゴースティング)**: コラボでは各自が自分の画面を配信するため、相手は自分の配信を見ればワナの位置が分かります。両方の配信を見た視聴者がチャットで答えを教えることもでき、「視聴者はゲームに影響しない」という原則が設計の外から崩れます。配信遅延では防げません(仕掛けは数ラウンド残るため)。
→ v2.1: 配信用の画面に自分の伏せた仕掛けを出さず、手元用の画面で操作する(4.1)

## 配信の専門家

## ボードゲーム専門家
| # | 問題 | v2.1 での扱い |
|---|---|---|
| 1 | 勝利条件が2つあり、ダメージやモンスターの定義がない | ゴール到着の1つに絞り、体力をなくした(3.2, 3.4) |
| 2 | 他人の宝箱を踏んでも得がなく、伏せマスは避けるのが常に正解 | 宝箱を横取りできるようにした(3.2) |
| 3 | 配信画面から自分のワナがばれる | 4.1 で対策 |
| 4 | 仕掛けるタイミングの競合、置ける範囲・重ね置きが未定 | 全員同時の仕掛けフェーズを移動前に締め切る。範囲制限、重ね置きなし(3.1, 3.2) |
| 5 | 2人・4人で遊び心地が変わる | 人数ごとの枚数、2人では中立の仕掛けを混ぜる(3.3) |
| 6 | トップ叩き、キングメーカー、終わらないゲーム | ワナが当たると仕掛けた人に得点、最大ラウンドで打ち切り(3.2, 3.4) |
| 7 | 手札制の中身がない | 山札の内訳公開、人数ごとの枚数(3.3)。具体的な枚数は試作で決める |
| 8 | 要素が多く説明しにくい、時間切れ・切断が未定 | ワナと宝箱の2種類に絞る、ボット代行(3.2, 3.5) |

## 想定ユーザー
主な声: 覗き見対策がない(コラボ配信者)。部屋の作り方・招待・アカウントの有無が不明、人数がそろわないと遊べない?(友人を誘う配信者)。何もできず物足りない、友人の読み合いが見えない(視聴者)。スマホで遊べるか不明、ルールが多い、本名を出してしまう不安(参加する友人)。
v2.1 での扱い: 覗き見対策(4.1)、アカウント不要・承認制の参加(4.2)、ボットで人数を埋める(3.5, 4.5)、振り返りと全公開(4.3)、手元用画面としてのスマホを試作で検討(4.1)、ルールを2種類に削減(3.2)、本名の注意書き(4.5)。戦績・マップの種類など「また遊びたくなる仕組み」は、基本の面白さを確かめてから検討。

## セキュリティ専門家
- 結論: 暫定推奨だった BaaS は、アクセスルールだけでは伏せたワナと公正なサイコロを守れない。サーバー側の処理が必要
- WebRTC(P2P)は参加者のIPアドレスが相手に見え、配信者の住所特定や攻撃につながりうる
- → v2.1: 推奨を C'(BaaS+サーバー関数)、次点を A(中継サーバー)に変更。B・C・D は採らない(5章)。リスクと対策は6章の表に反映
