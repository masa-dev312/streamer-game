# 企画レビュー記録(v2.1 → v2.2)

実施日: 2026-10-12 / 対象: [planning.md](planning.md) の v2.2 草案(伏せた仕掛けの配信表示を選べる形)
これまでのレビュー記録は共有フォルダの 旧案/ にあります。

5つの視点はいずれも Claude がその立場を想定して行ったレビューで、実在の専門家や実際のユーザーに聞いたものではありません。

## レビューのやり方の見直し
ユーザーから「視聴者にワナが見えるワクワク感というメリットがあるはず。穴の見つけ方が稚拙」と指摘を受けました。
実際、v2.1 のレビューでは配信の専門家が「視聴者だけが答えを知っている状態のハラハラが生まれにくい」と書いていたのに、覗き見対策を優先してその価値を捨てていました。リスクだけを数え、失う盛り上がりを比べていなかったのが原因です。
今回から次のように改めました。
- **盛り上がり(演出)の専門家**を加えて5つの視点にした
- どの視点にも「穴」と「メリット・伸びしろ」を同じ重さで出してもらった
- 企画書が守りのために削った面白さへの**反論**を求めた
- 二択で片方を捨てる前に、選べる設定にできないかを検討した

## 盛り上がりの専門家(新規)
削られていた盛り上がりへの反論:
| 反論 | v2.2 での扱い |
|---|---|
| 本命のコラボで「隠す」が推奨で、ハラハラが消えている。進む目が決まった後なら先に見せても読み合いは壊れない | 「来る来る」演出(3.1) |
| 仕掛ける場面が配信から消え、無言の時間になる | 仕掛けフェーズ中の配信画面、「誰の前に何個置いたか」公開案(3.1) |
| 中立の仕掛けが「誰のワナか」の因縁を薄める | 割合を小さくし、「ダンジョンのいたずら」というキャラとして見せる(3.3) |
| 演出の設計がない、打ち切りで盛り上がらずに終わる | 終盤の山場、リプレイと表彰、音を演出として設計(3.4, 4.6) |

足した仕掛け: 2つの行き先を光らせて迷わせる、自爆の演出、時系列リプレイと「横取り王」「自爆王」などの表彰、「ボットの仕掛けだけ表示」モード(ソロでも視聴者だけが答えを知る状態を作れる)。すべて採用(3.1〜3.4, 4.1)。
指摘: 「自分の仕掛けを表示」は配信者も知っている情報なので、生まれるのは「視聴者だけが知っている」ではなく「共犯」の楽しさ。本当に視聴者だけが知っている状態は「全部表示」と「ボットの仕掛けだけ表示」で作れる → 4.1 の表に反映。

## ボードゲーム専門家
問題点: 「自分の仕掛けを表示」が向く条件の書き方が誤り(問題は相手が配信しているかではなく、相手が自分の配信を見られるか)→ 修正(4.1)。ワナのポイントの使い道が同点時だけ → 仕掛けた人の前進に変更(3.2)。宝箱の中身と置き場所が未定 → 横取りで前進、自分の前にも置ける(3.2)。移動の順番と置ける範囲の基準が未定 → 最下位から移動(3.1)。
伸びしろ: 覗かれる前提の「見せかけ」の札(3.2)、中立の仕掛けを全人数で使うブラフ(3.3)、2つの行き先を見せ場にする(3.1)、終了時の表彰(3.4)、配信サービス側の予想機能をゲーム外で使う(4.3)。すべて採用。

## 想定ユーザー
ワクワクする瞬間(想定): コラボ相手のワナで通話中の全員が叫ぶ瞬間と答え合わせ(コラボ配信者)。「踏め!」と視聴者と共犯になる(友人を誘う配信者)。配信者がワナの手前で2つの目のどちらを選ぶか迷う瞬間(視聴者)。宝箱の横取りで配信者を出し抜く(参加する友人)。
不安と対応: モードが部屋に1つだけ → 自分だけ隠す側に寄せられる(4.1)。仕掛けフェーズ中の配信画面が未定 → 決めた(3.1)。モード選びが分かりにくい → 見本つきの選択画面(4.1)。配信にどう映るか不安 → 参加前の確認画面(4.5)。PC1台での操作 → 試作で確認(4.1)。

## セキュリティ専門家
方針: 送る情報の範囲をサーバー側でモードと役割ごとに分ければ、面白さを削らずに守れる。
採用: 送る範囲のサーバー側制御、観戦の役割はホスト発行のURLでのみ付与、観戦URLの伏せ字・期限・失効、開始後のモード変更不可(6章)。
参加者が別端末で観戦画面を開く問題は技術的に完全には防げない。本人確認などで縛ると実況企画を組みにくくなるため、接続数の表示と取り決めの確認にとどめる(失うものと比べた判断)。
