## 1. 設計の原則
1. **視聴者はゲームに影響しない**: 視聴者の入力はゲームに一切入らない。さらに、**配信画面から伏せた情報が漏れない**ようにして、チャットでの「答え教え」も成立させない
2. **参加者は招待制**: 部屋に入れるのは、ホスト(配信者)が承認した人だけ
3. **盛り上がりは参加者どうしの読み合いで作る**: 「仲間のワナを踏む」「仲間の宝箱を横取りする」瞬間が見どころ
4. **ルールは小さく始める**: 最初の版は「ワナ」と「宝箱」の2種類だけ
5. **判定はサーバー側で行う**: サイコロと伏せた情報を、参加者の端末に任せない

## 2. どんなゲームか
**2〜4人の参加者が、同じダンジョンを進むすごろくレース。** 毎ラウンド、全員が同時に「相手の行く先」にワナや宝箱を伏せて置き、そのあと順番に進む。ゴールに最初に着いた人が勝ち。

主な想定(暫定): **コラボ配信**(2〜4人の配信者がそれぞれ自分の配信で遊ぶ)。次点で、**配信者+友人**、**配信者1人+ボット**。

## 3. ルール(v2.1)

### 3.1 1ラウンドの流れ
1. **仕掛けフェーズ(全員同時)**: 全員が手札から仕掛けを選び、置ける範囲のマスに伏せて置く。制限時間で締め切る
2. **移動フェーズ(順番に)**: 手番の人はサイコロを2個振り、どちらかの目を選んで進む。止まったマスの仕掛けが公開されて発動する
3. **公開演出**: 発動した仕掛けは「Bさんが2ラウンド前に設置」のように、誰がいつ置いたかを短く振り返って表示する(切り抜きでも文脈が伝わるように)
- 公開演出の間は誰も操作しないので、仕掛けた本人もリアクションできる(仕掛けは移動の前に締め切るため、移動中の「後出し」も起きない)

### 3.2 仕掛け(最初の版は2種類)
| 仕掛け | 踏んだ人 | 仕掛けた人 |
|---|---|---|
| ワナ | 数マス戻る、または1回休み | ポイントが入る(または少し前進) |
| 宝箱 | **他人の宝箱を踏むと中身を横取りできる**。自分の宝箱なら回収 | 自分で回収できれば得 |

- 宝箱を横取りできるので、伏せマスは「避けるのが常に正解」にならない(踏むか避けるかの読み合いが生まれる)
- ワナが当たると仕掛けた人に得があるので、負けている人にも自分のための目的がある(キングメーカー対策)
- 体力の概念は持たない(説明と実装を軽くする)
- 置ける範囲は「各コマの何マス先まで」に制限し、同じマスへの重ね置きはできない(具体的なマス数は試作で決める)
- モンスター、アイテム、分かれ道は、基本の形が面白いと確認できてから追加を検討する

### 3.3 手札と山札
- 山札の内訳(ワナ何枚、宝箱何枚)は公開する。出た札を数えて残りを読む楽しみを作る
- 1ラウンドに置ける数と手札の枚数は、人数ごとに決める(4人でも盤面が埋まりすぎないように)
- **2人のとき**は、山札から「持ち主のいない中立の仕掛け」を混ぜる(伏せマスの持ち主が相手に確定してしまうのを防ぐ)
- 後ろにいる人は手札の補充が少し多い(逆転の仕組み。ブレーキがかかりすぎないよう試作で調整)

### 3.4 勝利条件と終わり方
- **ゴールに最初に着いた人が勝ち**(勝利条件は1つに絞る)
- 最大ラウンド数で打ち切り、その時点で最も進んでいる人が勝ち。同じなら、ワナのポイントが多い人が勝ち
- 目標プレイ時間から最大ラウンド数を逆算する(具体的な分数は試作で決める)
- ゲーム終了時に、全員の仕掛けの配置を全公開する(「実はここに置いていた」の答え合わせを見どころにする)

### 3.5 時間切れ・切断
- 手番や仕掛けの時間切れは、ボットが代わりに操作する
- 切断した人は再接続トークンで同じ席に戻れる。戻るまではボットが代行する
- ホストは「一時停止」「抜けた人を除外」ができる
- 伏せた仕掛けの公開はサーバー側が行うので、仕掛けた本人が不在でも進行が止まらない

## 4. 配信まわり(配信の専門家のレビューを反映)

### 4.1 配信の覗き見(ゴースティング)対策
- **配信用の画面には、自分の伏せた仕掛けを表示しない**(既定でオン)
- 手札と仕掛けの配置は**手元用の画面**で操作する。手元用の画面は、OBS に取り込まない別ウィンドウか、スマホのブラウザを想定(どちらにするかは試作で決める)
- 配信遅延では防げない(仕掛けは数ラウンド残るため)ので、表示しないことで防ぐ
- 視聴者が両方の配信を見ても、配信画面には公開済みの情報しか映らない

### 4.2 部屋への参加
- 部屋コードと招待URLは**画面上では伏せ字が既定**。コピーボタンで渡す
- ホストが参加を承認する。開始後は部屋をロックし、追い出しもできる。コードには有効期限をつける
- アカウント登録は不要(匿名認証で席と本人を結びつける。方式は要確認)

### 4.3 視聴者の見どころ
- 公開演出と振り返り表示、ゲーム終了時の全配置公開
- 残りの手札の枚数や山札の残りなど、公開情報は配信画面に出す
- 画面に1行のルールを常に表示する。初回は案内つきのラウンドにする
- 視聴者が見ている前で答えを知る「観戦ビュー」は、覗き見対策とぶつかるため入れない

### 4.4 配信画面のレイアウト
- 16:9 の固定レイアウト。カメラやチャットのオーバーレイを置く空き枠を設ける
- 「配信セーフモード」(伏せ情報・部屋コードを出さない)を既定にする

### 4.5 名前と同意
- 表示名は参加者が入れる。本名を入れないよう注意書きを出す
- ホストは表示名を上書き・伏せ字にできる(配信者でない友人を守るため)
- ボットは**ボットと分かる名前と見た目**にし、性格(仕掛けの癖)を持たせて、ソロ配信でもリアクションしやすくする

### 4.6 音
- BGM・効果音は自作か、配信での利用が明記された素材だけを使う。BGM は単独でオフにできる(各サービスの扱いは要確認)

## 5. 通信方式
伏せた仕掛けとサイコロを公正に扱うには、**サーバー側で判定する仕組み**が必要(セキュリティ専門家の指摘)。

| 方式 | 伏せた仕掛けを隠せるか | サイコロ・判定 | 参加者のIPアドレス | 運用・費用 |
|---|---|---|---|---|
| A. 中継サーバー(WebSocket) | ○ サーバーだけが持つ | ○ サーバーで行う | 相手には見えない | サーバーの運用が必要 |
| B. P2P(WebRTC) | △ 誰か1人が全部を持つ | × 自己申告になる | **相手に見える**(配信者の住所特定や攻撃につながりうる) | シグナリングと TURN が必要 |
| C. BaaS(アクセスルールのみ) | △ 文書の分け方で隠せるが判定が難しい | × クライアントの申告 | 見えない | 設定ミスで漏れ・料金急増のおそれ |
| C'. BaaS+サーバー関数 | ○ | ○ | 見えない | サーバー関数の料金プランは要確認 |
| D. 1台で交代 | × | ○ | 該当なし | 不要だが伏せ情報が成立しない |

**推奨: C'(BaaS+サーバー関数)、次点 A。** B は参加者のIPアドレスが相手に見えるため採らない。C と D は伏せ情報が守れないため採らない。サービスの選定・料金・無料枠は着手前に確認する。

## 6. セキュリティ
| 重要度 | リスク | 対策 |
|---|---|---|
| 高 | 伏せた仕掛け・サイコロの不正 | 判定と乱数はサーバー側。仕掛けの中身は踏まれるまで持ち主以外に送らない |
| 高 | 配信画面から伏せ情報が漏れる | 4.1 の配信用画面と手元用画面の分離 |
| 高 | 部屋コードの流出・乱入 | 4.2 の伏せ字・承認・ロック・追い出し・期限。部屋の一覧は読めないようにする |
| 高 | BaaS の設定ミス・料金の急増 | テスト用のルールのまま公開しない。ルールのテストを用意。Web 用のAPIキーは秘密でない前提で、守りはルールとサーバー関数に置く。予算アラートは通知のみで自動停止しない可能性があるため、上限に達したときの停止手順を決める(要確認) |
| 中 | なりすまし | 匿名認証で席と本人を結びつけ、書き込みは本人の席だけに許可 |
| 中 | 表示名の悪用 | 正規化、制御文字・幅ゼロ文字の除去、長さ制限、HTMLとして解釈しない。サーバー側でも長さと文字種を検証 |
| 中 | 個人情報 | 保存は表示名と内部IDだけ。対局後に部屋データを自動で消す(方法は要確認) |
| 中 | 外部ライブラリ | 同梱してバージョンを固定。GitHub Pages ではレスポンスヘッダーを付けられないため、CSP は meta タグで設定(制約は要確認) |

## 7. 技術方針
- ブラウザで動く素のJS + Canvas(よけゲーのコードは使わない)
- 画面は GitHub Pages、通信と判定は5章の方式
- ボット相手に1人で遊べるモードを最初に作る(ルールの面白さと人数ごとのバランスを、通信なしで先に確かめる)

## 8. 決めてほしいこと
| 質問 | 選択肢 | 推奨 |
|---|---|---|
| 自分の伏せた仕掛けを自分の配信に映すか | 隠す / 映す(覗き見される前提) | **隠す に決定(2026-10-12)**。手元用の画面で操作 |
| 主な遊び方 | コラボ配信 / 配信者+友人 / ソロ+ボット | **コラボ配信**を主に、ほかも遊べるようにする |
| 通信方式 | C' / A | **C'**(サーバーの運用が不要)。サービスの料金を確認してから確定 |
