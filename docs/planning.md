# 配信者向けマルチプレイゲーム 企画書(v1.1)

作成日: 2026-10-12 / ステータス: 案1「チャットダンジョン」に決定(2026-10-12、コード未着手)
更新: v1.1 でボードゲーム専門家・想定ユーザー・セキュリティ専門家のレビューを反映。議論の記録は [review.md](review.md)

v0.2 までの「よけゲーを土台にする案」は、ユーザーの指示(2026-10-12)により取りやめ、**よけゲーを使わない新しいゲーム**として作り直しました。旧案はプロジェクトの共有フォルダ(streamer-game/旧案/)に残しています。
旧案のレビューで得た、ゲームの種類によらない学び(配信遅延・入力しやすさ・名前表示の安全対策)は引き継ぎます。

> 本書の数値(人数・秒数・点数など)はすべて**初期案の設計値**です。市場データや実測に基づく数値ではありません。
> 外部サービス(Twitch / YouTube)の仕様で「要確認」と書いた項目は、着手前に公式ドキュメントで確認します。

## 1. 前提(旧案から引き継ぐ設計の原則)

1. **配信遅延に強いこと**: 視聴者の映像は数秒遅れるのが一般的。視聴者にリアルタイムの精密操作をさせない
2. **参加の手間がないこと**: チャットに打つだけで参加できる。インストールや登録は不要
3. **大人数でも少人数でも成立すること**: 大人数で「自分の入力が無意味」にならず、少人数で「盛り上がらない」にもならない
4. **配信者の名前を叫ぶ瞬間を作ること**: 視聴者の名前がゲームの中に出てくる
5. **安全に名前を出すこと**: 不適切な名前・文字列が配信に映らない仕組みを最初から入れる

## 2. 新しい案の比較

### 案1:「チャットダンジョン」(ターン制すごろく)
配信者は勇者になり、すごろくのようなマップをサイコロで進んで最深部の宝を目指す。**視聴者はダンジョンの住人**として、マスにワナやモンスターを仕掛ける。仕掛けたマスには名前が出る。
- 1ターンの流れ: 視聴者が仕掛ける時間(例: 20秒)→ 配信者がサイコロを振り、分かれ道を選ぶ → 止まったマスのワナ・モンスターと対決
- 配信者の「どっちの道に行く?」という迷いと、サイコロの運が配信の見どころになる
- おうえん派は回復の泉や宝箱を置ける

### 案2:「ことば城の攻防」(チャットの言葉で攻める)
配信者は城の主。視聴者は**お題に合う言葉をチャットに打つ**と兵士が1体出て城へ進む(例: お題「赤いもの」→「りんご」「ポスト」)。配信者は、出てきた言葉の中から**ダメな答え(お題に合わない)を見つけてはじく**ことで城を守る。
- 言葉そのものが攻撃になり、ツッコミが配信の見どころになる
- ただし「何を表示するか」が自由入力になるため、不適切な言葉の対策が最も重い

### 案3:「せーのでピタリ」(チャット予想バトル)
配信者がお題(例:「自分が今から3回サイコロを振った合計は?」「この絵は何点?」)を出し、視聴者が予想を数字や選択肢で送る。**ピタリ賞の人の名前**を発表し、ラウンドを重ねて得点を競う。
- 一番簡単に作れ、遅延の影響もほぼない
- 配信者は進行役になりやすく、配信者自身が「遊んでいる」感覚は弱い

### 比較表
(v1.1 で「繰り返し遊びたくなるか」「1プレイの長さ」を追加し、案1の評価を見直しました)

| 観点 | 案1 チャットダンジョン | 案2 ことば城 | 案3 せーのでピタリ |

| 盛り上がり(配信者のリアクション) | ◎ ワナを踏む瞬間に仕掛けた人の名前が出る | ◎ ツッコミが生まれる | ○ 発表の瞬間に集中 |
| 配信者自身が遊ぶ感覚 | ○ 移動の選択・道選び・対決(v1.1 で選択肢を追加した前提) | ○ はじく判断 | △ 進行役 |
| 視聴者の参加しやすさ | ○ コマンド+マス番号(短い書き方で負担を減らす) | ○ 言葉を考える必要がある | ◎ 数字・選択肢を打つだけ |
| 配信遅延への強さ | ○ ターン制で影響は小さいが、受付の締め切りには余裕が必要 | ○ 判断に時間差が出る | ◎ |

| 開発の重さ | 中 | 中〜大(言葉の判定) | 小 |

### 推奨:**案1「チャットダンジョン」**

理由:
1. **ターン制**なので、配信遅延の影響が小さい(受付の締め切りに余裕を持たせれば対応できる)
2. 配信者が移動・道・対決で判断するので、受け身にならない
3. 視聴者は**決まったコマンドだけ**で遊べるので、表示するのは名前だけ。自由入力の言葉を画面に出さずに済む
4. すごろく・ワナ・分かれ道は、ボードゲームの知見がそのまま活かせる

弱点(レビューでの指摘): 今のままでは「サイコロ任せで、人数が多いほど配信者が負けるすごろく」になりやすい。**移動の選び方**と**人数に合わせたバランス**を試作の最初の検証項目にする。
案3は作りやすく、案1の待ち時間を埋める「予想」として取り込む。案2は自由入力の言葉を表示する安全対策が重いため見送り。

## 3. 推奨案の詳細:「チャットダンジョン」(仮題)

### 3.1 コンセプト
**「配信者は勇者、チャットはダンジョン。仕掛けた人の名前つきのワナを踏み抜け」**

- 1プレイの目標時間を先に決め、ターン数と受付の秒数を逆算する。仮の目標は**配信の1コーナーとして収まる長さ**とし、具体的な分数は試作で決める
- ターン数・受付の秒数は配信者が設定で変えられる
- マップは毎回ランダムに作る

### 3.2 役割
| 役割 | 誰 | やること | 勝利条件・ごほうび |
|---|---|---|---|
| 勇者 | 配信者 | 移動の選択、分かれ道の選択、モンスターとの対決、アイテムの使用 | HPが残ったまま最深部の宝に着く |
| ワナ師 | 視聴者 | 先のマスにワナ・モンスターを仕掛ける | 勇者のHPを0にする。仕掛けが当たった人は名前を大きく表示 |
| 精霊 | 視聴者 | 回復の泉・宝箱を置く | 勇者が泉や宝箱を使ったときに名前を大きく表示。最後に「救った人」として発表 |

### 3.3 移動のルール(配信者の選択を増やす)
v1.0 は「サイコロで進むだけ」で、選択が分かれ道しかなかった(ボードゲーム専門家の指摘)。次の2方式を試作で比べる。
- **方式A: サイコロ2個**: 2個振って、どちらかの目を選んで進む
- **方式B: 移動カード**: 1〜6の移動カードを手札に持ち、各カードを1回ずつ使う

どちらでも「どのマスに止まるか」を配信者が選べる。

### 3.4 仕掛けのルール
| 仕掛け | 効果 |
|---|---|
| ワナ | 踏むと必ずダメージ。避けられない |
| モンスター | 対決(サイコロ勝負など、1行で説明できる判定)。**勝つとアイテムか最大HPが手に入る**、負けるとダメージ |
| 回復の泉 | 踏むと回復 |
| 宝箱 | 踏むとアイテム |

- **1人1ターンに1つ**まで仕掛けられる(連投・複数アカウントによる集中の抑制)
- **仕掛けは伏せておき、踏んだときに公開**する方式と、見えている方式を試作で比べる。伏せる場合は「止まりやすいマスに積むだけ」が最善でなくなる
- 分かれ道は「危険だが近道・宝がある道」と「安全だが遠い道」のようにリスクと見返りを付ける
- 同じマスに仕掛けが集まると強くなるが、強さは**人数そのものではなく「参加者のうち何割がそこに入れたか」**で決め、**1マスの強さに上限**を設ける
- **1ターンの被ダメージにも上限**を設け、**生き残れる道が最低1本ある**ようにする(大人数での理不尽な即死を防ぐ)
- 勝率の目標を先に決め、ボットだけの練習モードで人数を変えて調整する

### 3.5 逆転の仕組み
- モンスターに勝つとアイテムや最大HPが手に入る(HPが減る一方にならない)
- 危険な道ほど近道や宝がある
- 配信者が余裕のときはダンジョンが深くなる、苦しいときは精霊の効果が上がる、などの補正を試作で検討

### 3.6 1ターンの流れ(待ち時間を減らす)
1. **勇者フェーズ**: 配信者が移動・道を選ぶ。止まったマスの仕掛けを公開して発動。仕掛けた人の名前を大きく表示
2. **同時に、次の区間の受付**: 勇者フェーズと演出の間に、視聴者は**その先の区間**へ仕掛けを入れる(待ち時間を重ねる)
3. **予想**: モンスターとの対決の前に、視聴者は勝ち負けを予想できる(案3の取り込み)。当たった人は得点
4. 受付の締め切り前に**カウントダウン**を表示。締め切りは**ゲームが受信した時刻**で判定し、締め切り後に届いたコマンドは捨てる

### 3.7 チャットコマンド
| コマンド | 短い書き方(同じ扱い) | 効果 |
|---|---|---|
| `!wana 12` | `わな12` `ワナ12` `!わな12` | 12番のマスにワナ |
| `!mon 12` | `もん12` `モン12` | 12番のマスにモンスター |
| `!izumi 12` | `いずみ12` | 12番のマスに回復の泉 |
| `!takara 12` | `たから12` | 12番のマスに宝箱 |
| `!kachi` / `!make` | `かち` `まけ` | 対決の予想(勝つ/負ける) |

- 「!」なし、スペースなし、全角スペース、全角数字も受け付ける(スマホで入力モードを何度も切り替えなくて済むように)
- **マス番号は絶対番号**(勇者が進んでも番号は変わらない)。遅延で狙いと違うマスに仕掛ける事故を防ぐ
- 受け付けるのは「いま仕掛けられるマス」の番号だけ。範囲外・通過済み・数字以外は捨てる
- 受け付けたら、名前つきで短く表示する。コマンド一覧とカウントダウンは常に画面に出す
- ワナ師になるか精霊になるかは、使ったコマンドで自動的に決まる(陣営の登録は不要)

### 3.8 名前の出し方
- 1つのマスに複数人が仕掛けた場合、マスには**代表1名と「他N人」**だけ出す。代表は仕掛けた人の中から抽選(打つのが速い人だけが有利にならないように)
- 発動したときは、仕掛けた人の名前を流して表示する
- 少人数補正のボットは、**ボットと分かる固定の名前と見た目**にする(実在の人と誤解されないように)

### 3.9 また遊びたくなる仕組み
- 毎回変わるマップ
- プレイ後の「ワナ師ランキング」「救った人」「予想王」と名前つきの振り返り
- 勇者の記録(到達した深さなど)
- ランキング・記録は**配信者の端末内だけの参考値**とし、全体ランキングは作らない(サーバーなしでは改ざんを防げないため)

## 4. 配信者の導入手順(目標)
1. ゲームの設定画面でチャンネル名を入れる
2. ブラウザソース用のURLが表示されるので、OBS などの配信ソフトに貼る
3. 推奨の画面サイズと、背景を透過する手順を1ページの導入ガイドにまとめる(配信ソフト側の対応は要確認)

- 設定画面と、配信に映す画面を分ける
- 配信者用の一時停止・緊急停止を用意する

## 6. セキュリティ方針
旧案のレビュー結果をすべて引き継ぎ(v1.0 では一部が漏れていた)、新案特有のリスクを加えた。最大のリスクは、**視聴者が送った文字列が配信者の画面に映ること**。

### 6.1 旧案から引き継ぐもの
| 重要度 | リスク | 対策 |
|---|---|---|
| 高 | 不適切な名前が配信画面に映り、配信者が規約違反を問われる | 名前表示のオン/オフ、NGワード、使える文字の制限、長さの上限。削除・BANされた人の表示はすぐ消す |
| 高 | 文字列がHTMLとして解釈される(XSS) | Canvas か `textContent` で表示し、innerHTML は使わない。決まったコマンド以外は捨てる。壊れた入力でも落ちない解析処理 |
| 高 | 荒らし・ボットの大量コマンドで配信が止まる | ユーザーIDごとのクールダウン、全体の上限、待ち行列の上限、あふれた分は捨てる。一時停止・緊急停止 |
| 高 | YouTube のAPIキーが漏れる | キーをURLに入れない(OBSの設定やスクリーンショットに映るため)。入力欄は伏せ字。保存は端末内(localStorage)のみで、保存しない選択肢も用意 |
| 中 | Unicode の悪用・なりすまし | NFKC で正規化、制御文字・幅ゼロ文字の除去、見た目の文字数で切り詰め。配信者・モデレーターと見分けにくい名前は区別して表示 |
| 中 | OBS ブラウザソースで長時間動作 | 権限は最小限(OBS独自のJS機能の扱いは要確認)。自動再接続、メモリリーク対策、異常時は止まる |
| 中 | 外部ライブラリ/CDN | 同梱してバージョン固定、SHA-256 を記録。CSP の接続先は必要なものだけ |
| 中 | 利用規約違反 | Twitch・YouTube の規約を着手前に公式文書で確認 |
| 低 | 視聴者名の扱い | 外部に送らない。端末内の記録は削除できるようにする |

### 6.2 新案特有のもの
| 重要度 | リスク | 対策 |
|---|---|---|
| 高 | 名前がマスに何ターンも残る(BANされた人の名前も残る) | 削除・BAN通知を受けたらその人の仕掛けと名前をすぐ消す。マスには代表1名と「他N人」だけ。配信者がマス単位で消せる |
| 高 | マス番号の想定外の入力(`03`、`-1`、`3.5`、巨大な数、余分な引数、範囲外) | 正規化の後に数字だけ許可。範囲は「いま仕掛けられるマス」に限定。それ以外は捨てる |
| 高 | 1マスへの集中で確実に死ぬ状態が作れる | 1マスの強さの上限、1ターンの被ダメージ上限、生き残れる道の保証、強さは割合で決める |
| 中 | 複数アカウントでの組織的な妨害 | 1人1ターン1つ、効果は頭打ち、配信者の拒否権。配信サービス側の設定(フォロワー限定チャットなど)との併用を案内(仕様は要確認) |
| 中 | 締め切り後の駆け込み(道を選んだ後にその道へ仕掛ける) | 受信時刻で判定し、受付時間外のコマンドは捨てる |
| 中 | ランキング・記録の改ざん | 端末内だけの参考値にする。全体ランキングは作らない |
| 低 | ボットが実在の人に見える | ボットと分かる固定の名前と見た目 |
